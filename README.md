# 谱系 KIN · 可交互 Web App MVP

一个中文、蓝紫色关系网络的课程演示。React + Vite + TypeScript + React Flow + Tailwind CSS，完全在浏览器内运行。**全部人物与关系均为虚构**。算法只能发现连接，不能定义关系。

## 第一阶段：3D 个人谱系

个人谱系新增 `react-force-graph-3d` / Three.js 空间视图，原有 React Flow 用于 2D 路径阅读与碰一碰结果。3D 模块仅在打开空间视图时加载。

1. 初始从林知夏和少量直接关系开始。点击球形节点或画布下方的人物按钮，例如周予安，会聚焦该人物并展开已授权的下一层。
2. 点击陈见川继续发现许星遥。选中人物及从自己的可见路径高亮，信息面板明确说明是否为直接确认关系。
3. 拖动旋转、滚轮缩放、右键拖动平移；触屏单指旋转、双指缩放和平移。使用「查看全图」「回到自己」调整镜头。
4. 「收起此分支」关闭当前人物的向外展开；经其他已展开分支仍可到达的人物会保留。「收起到第一层」恢复初始探索范围。
5. 切换「2D 路径阅读」：选中某人时只呈现到该人物的准确连接路径；点击「回到自己」显示当前可见网络。切换视图保留探索进度。
6. 正式、私人、候选切换时从第一层重新开始。私人直连仅供关系参与者阅读，不向外传递权限；候选连接为虚线推荐，不提供真实关系路径。

布局按连接层级与分支固定位置，**空间距离不代表情感亲密度**。节点及连线有短暂生长动画；姓名朝向镜头并按屏幕位置避让。没有自动旋转和持续力模拟漂移。渲染空闲时暂停，鼠标交互、镜头调整或关系变化时唤醒。单视图最多 24 位人物，目前虚构数据共 24 人，其中 23 人可逐层连接，苏望野保留为独立用户；像素比上限 1.5，并支持系统的减少动态效果设置。

新增分支体验：初始只显示自己和 4 位直接联系人。依次探索林书禾、林砚秋、何听澜的亲属与书友网络；周予安、陈见川、许星遥的创作网络；唐以宁、温栖、宋予澄的工作网络，可以逐层发现完整的 23 人网络。何听澜的私密直连不能转授权，需要先展开林书禾，沿双方允许共享的另一条路径到达她。点击「回到自己」再「查看全图」能观察完整分叉。更新会补入新增示例边，保留本机已有的私密、淡化、退出、认领和历史，不需要重置演示数据。

如果设备无法创建 WebGL 视图，或图形上下文中断，界面会提示切换「2D 路径阅读」。小屏幕也可通过人物按钮探索，避免依赖精确点中球体。

第一阶段检查：`npm test` 共 24 项，覆盖原有规则、旧数据补入、新增分支、布局间距和可见路径；`npm run build` 检查 TypeScript 和 Pages 资源构建。另在本地生产预览中检查 3D 点击、旋转、聚焦、展开收起、2D 路径、私人/候选层、身份切换、390px 手机布局和碰一碰回归；扩充分支后检查了 23 人全图、新增四层路径和私密分支过滤。真实手机硬件、低配电脑帧率及禁用 WebGL 后的回退仍需设备验证。

## 完整作品体验

每页都有可收起的四步体验路线：个人谱系 → 模拟碰一碰 → 关系管理 → 关系历史。页尾的「关于《谱系 KIN》与这次设计」解释作品起点及 AI 协作，创作协作与产品内的授权寻路保持区分。

碰一碰使用 Motion，过程依次为人物卡片靠近 → 双方临时配对 → 逐边授权寻路 → 路径按人物展开。只有双方同意才开始配对；拒绝时不寻路、不创建会话。成功、无可见路径、拒绝、手动结束、取消、到期与运行异常都有独立反馈。可使用「默认示例」「试试无路径」「试试拒绝」准备演示，之后点击开始；默认示例是当前身份到陈见川（陈见川身份时为林知夏），能否找到路径仍取决于实际保存的关系和权限。

动画与所有等待可取消：修改任意共享设置、切换身份或离开碰一碰页面会清除路径和定时器；配对过程中也可主动取消。两分钟从临时配对成功开始计时，不续期。系统启用减少动态效果时，缩短等待并去除位移动画和循环波纹。碰一碰动画模块与 3D 模块分别按需加载。

找到路径后，可申请直接关系认领。发送申请后使用「切换为对方并回应」，由接收方选择接受/拒绝和自己的共享权限；再点「回到林知夏」继续演示。接受后默认仍遵循双方各自的私密选择。淡化、恢复、个人授权和单方退出位于关系生命周期，历史页面保存全部变化。

本轮在独立的本地测试演示中实际走通：取消配对、修改范围中断、切换身份中断、成功/拒绝/无路径、逐步展开、推导到认领、接收方接受、默认私密、淡化与恢复、个人权限、单方退出、客观关系保护，以及刷新后历史保留。另在用户预览中等待真实两分钟，确认到期清除路径；检查桌面与 390px 手机布局。自动化的 24 项逻辑测试与生产构建通过。真实手机硬件和减少动态效果的设备设置尚未实测。

## 本地启动

需要 Node.js 22.12+（或 Node.js 24 LTS）和 npm。

```sh
npm install
npm run dev
```

打开终端显示的地址，默认是 `http://localhost:5173/KIN.github.io/`。

```sh
npm test           # 关系和授权的自动化测试
npm run build     # TypeScript 检查 + 生产构建
npm run preview   # 本机预览 dist，默认 http://localhost:4173/KIN.github.io/
```

使用 `package-lock.json` 固定依赖；CI 使用 `npm ci`。初次下载需要网络。

## 建议演示顺序

1. 以 **林知夏** 开始，在「个人谱系」点击 **周予安**：下一层出现 **陈见川**。点击林书禾可继续展开何听澜。切换正式、私人、候选层查看差异。
2. 打开「模拟碰一碰」，选择 **陈见川**，双方保留三种类型和 3 层、同意授权，点击开始。观看卡片靠近、临时配对、寻路及 `林知夏 → 周予安 → 陈见川` 逐步展开。该结果标注为系统推导，不自动创建直接关系。
3. 把任一方层数改为 **1**，或仅共享「朋友」，重新开始：没有可见路径。选择独立节点 **苏望野** 也没有路径。取消任一方同意后开始：拒绝授权，不进行寻路。
4. 恢复默认共享范围并寻路，点击「可选：申请直接关系认领」进入关系管理，向陈见川发送申请（默认私密）。点击「切换为对方并回应」或右上角切换为 **陈见川**，在「待我回应」中接受，单独选择接收方是否允许共享。
5. 切回林知夏：新关系有「双方确认」来源标签。双方都允许共享时才能参与寻路；任一方私密都会阻断该直接边。测试拒绝：向苏望野申请，再切换为苏望野点击拒绝；不会新增关系。
6. 在「关系生命周期」对自愿共同关系执行保持、单方淡化、权限变更或单方退出。「淡化」只影响自己的视图；「退出」终止该共同边，保留历史。林知夏与林书禾的客观关系不能退出删除，但可以关闭自己的共享许可。
7. 刷新查看关系及历史仍在。碰一碰会话只保存在内存，配对成功后 2 分钟到期或手动结束后清除；改权限、改范围、切换身份或离开本页也会关闭旧会话。
8. 「重置演示数据」确认后清除认领和历史，恢复默认人物与关系。

## 数据和隐私规则

- **正式谱系**：客观关系，以及双方同意共享的直接确认关系。关闭客观关系的共享不会删除该事实，但它不再进入共享寻路。
- **私人谱系**：至少一方未授权共享的自愿直接关系。关系双方可在自己的视图查看，第三方不能沿此边展开。
- **候选谱系**：演示中的可申请人物推荐，以虚线呈现。不写入有效关系、不参与路径搜索、不自动确认。推荐只是示例列表，不是智能匹配服务。
- 每条关系独立保存双方共享权限；寻路使用**双方选中类型的交集**，并要求每条边原来的双方都允许共享。两人所选层数的较小值为本次**路径最大边数**（1 层就是 1 条边）。
- BFS 只在过滤后的有效图上运行。没有可见路径并不意味着现实中没有关系。
- 认领只建立自愿共同关系，不能凭表单认证或改变法定/客观身份。只能由申请接收方回应。已退出关系必须重新发起并接受申请才能建立新的共同边。
- `localStorage` 键 `kin-demo-v1` 保存关系、认领和演示总历史。损坏或不兼容的数据会恢复初始示例。存储不可用时页面提示无法持久保存。
- 当前模拟身份默认林知夏，界面选择和临时会话不持久化。演示总历史可查看所有模拟身份的操作。
- 这是单浏览器本地 MVP，不包含真实登录、真实 NFC、后端鉴权、多设备同步或法定身份核验。切换身份是演示功能，不是安全隔离机制。

## GitHub Pages 部署

- `vite.config.ts` 设置 `base: '/KIN.github.io/'`。
- `.github/workflows/deploy.yml` 在 `main` 分支 push 或手动 `workflow_dispatch` 时运行：`npm ci → npm test → npm run build → 上传 dist → Pages 部署`。
- 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
- 预期公开地址：`https://notsherly.github.io/KIN.github.io/`，只有代码推送且工作流成功后才会上线。
- 导航使用 hash，如 `/KIN.github.io/#tap`。刷新仍请求项目根目录，不产生 SPA 子路由 404；无需 404 重定向脚本。
- 工作流仅授予读取源码、写 Pages 和 OIDC 所需权限。Node.js 使用 22。

部署内容通过常规 Git 提交推送到 `main`；不需要上传本机的 `node_modules` 或 `dist`。
